# Review of origin/claude/c7-search-api-contract-uzma46 (BLOCK)

The branch (one commit, 79bc55f) declares the four search-and-ask operations in backend/apps/search/api.py and schemas.py, mounts the router, sends each to a stub that raises a 501 `not_built` ProblemError behind the real gate (SessionAuth + search.use for search/ask/rateAnswer, ApiKeyAuth + search:read for findSimilar), adds four input-cap settings with env overrides, deletes the four now-delivered lines from contract_drift_pending.txt, writes the INPUT_DELTAS rows, and covers it with tests_contract.py (gate-before-stub, 401/403 with requiredPermission, 422 on missing q / limit 1000 / unknown enum / extra field, operation-id registration). The backend contract is sound on security: RFC 9457 with a code, no trace, no logging, no model reachable from ask, pagination 20/100 with 422 not clamp, POST bodies keep tenant text out of URLs. It misses its brief in three ways that will cost rework downstream: Ask is declared as one JSON body rather than the NDJSON stream the brief and CLAUDE.md section 6 require (main's LLM adapter already streams); the stubs live in hybrid.py and ask.py::rate_answer while the logic tasks that must replace them own retrieval.py and governance/ai_log.py and are forbidden to edit api.py; and five frontend files were written although the brief says "no frontend work here" and frontend/src/features/search/** is owned by c7-search-screen and c7-ask-screen, and they cannot typecheck on the branch because api.generated.ts carries none of the schemas they import. The pending-file deletions, the identity ID-S21 test edit and the kinds.py entries are explained below; the first is legitimate and required by contract_drift.py, the other two are low.

## Findings

### [MEDIUM] brief: Ask is declared as a single JSON Answer, not the stream the brief and the budget require
- Where: `backend/apps/search/api.py`:87
- Scenario: The brief (CHUNK7_TASKS c7-search-api-contract, and DEFAULTS TAKEN) says: declare `ask` as newline-delimited JSON with a `start` event carrying the answer id, `statement` events and a terminal `answer` event, and write the INPUT_DELTAS row saying `POST /ask` answers a stream and why (first token under 2 s, CLAUDE.md section 6). The branch declares `response=Answer` (api.py:87) and ask.py:132 returns `Answer`; the INPUT_DELTAS rows (docs/inputs/INPUT_DELTAS.md new lines 325-371) never mention a stream. Main already has `stream()` on the LLM adapter (backend/apps/shared/adapters/llm.py:88). c7-ask-backend is told to stream from ask.py but may not edit api.py, so it either buffers the whole answer into one JSON body and misses the 2 s first-event budget SRC-S9 tests, or a second contract task reopens api.py and the frontend `useAsk` mutation written here (hooks.ts:27) has to be rewritten too.
- Fix: Declare `ask` as a streaming response (a `StreamingHttpResponse` with `application/x-ndjson`, `response=None` or an explicit content schema for the terminal `Answer`), keep the stub raising 501 before any stream starts, and add the INPUT_DELTAS row that names `POST /ask` and says the response is a stream of the designed shape because of the first-token budget.

### [MEDIUM] conflict: Stubs live in modules no downstream task owns, so the logic tasks cannot replace them
- Where: `backend/apps/search/api.py`:77
- Scenario: api.py:77 and :84 call `hybrid.run_search` / `hybrid.find_similar` and api.py:105 calls `ask.rate_answer`. - Fix: Rename hybrid.py to retrieval.py with `search` and `find_similar`; move the `rateAnswer` stub to `backend/apps/governance/ai_log.py::set_feedback` and import that from api.py; keep ask.py's stub named `answer` as the brief names it.
