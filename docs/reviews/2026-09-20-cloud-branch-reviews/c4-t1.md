# Review of origin/claude/c4-t1-obligation-proposals-00zwiq (BLOCK)

The branch (one commit, ef412ea) adds the new_obligation_version proposal kind. The kind has a named payload (summaries keyed by language with originalLanguage and isMachine, effectiveFrom with a precision, optional dimension:key terms). It adds one importable source check (check_field_sources, 422 source_missing), refuses a missing or retired target obligation, and adds the corrected_payload/corrected_by/corrected_at columns and the proposed_in_tenant boolean. It also adds a ProposalTenant link table under forced tenant-only RLS, audits proposal.created and proposal.replayed under the database's active tenant, and rewords and un-skips PRO-S1. On the security core it is clean: the create path writes only proposal, proposal_tenant and audit/outbox rows in the request transaction. The added library/logic.py function is a pure read. The library fence, four-eyes constraint and API-key scopes are untouched, and the migration applies rls_operations to proposal_tenant with no tenant column on proposal. It fails one done-condition by editing apps/library/logic.py outside its owned paths (disclosed and needed because of the fence). The branch is blocked by one MEDIUM: the "source per changed field" rule, the rule this task exists to enforce, accepts any non-blank string of any length, and agents supply these values. Also, the new obligation door carries none of the INV-08 standards check that app.md section 1 says runs at POST /proposals. No standard is seeded yet and the chunk 4 brief assigns neither PRO-S10 nor PRO-S11, so this is a planning gap to settle before standards land, not a defect of this branch.

## Findings

### [MEDIUM] security: A field source is any non-blank string: no link check, no length cap, and keys that name no changed field are accepted
- Where: `backend/apps/proposals/logic.py`:249
- Scenario: An agent key with proposals:write POSTs /proposals kind new_obligation_version with fieldSources {"summaries.sv": "n/a", "summaries.en": "see above", "effectiveFrom": "javascript:alert(1)", "terms": <2 MB of pasted text>, "dutyType": "x"}. check_field_sources only tests field_sources.get(field, "").strip(), so the request answers 201. Every value is stored on proposal.field_sources (a free JSON column, unlike source_url, which is a URLField of 2000 chars). T6 re-runs the same function over the corrected payload, so the value reaches the library with nothing traceable behind it. The rule is met in form only, although docs/inputs/schema.sql:372 defines field_sources as 'one source link per changed field' and PRO-S10 already expects a non-URL field source to be refused. The console queue (T10/T17) will render these agent-supplied strings as the source beside the diff.
- Fix: In check_field_sources, require each sourced field's value to be an absolute http(s) URL of at most 2000 characters (django URLValidator(schemes=["http", "https"]), matching Proposal.source_url), and refuse fieldSources keys that name no field in sourced_fields(payload) with 422 validation_error. Add tests_create cases for a placeholder, a javascript: URL, an over-long value and an extra key. Doing it inside the one function means T6's approval re-check inherits it.

### [LOW] correctness: Scope terms are neither de-duplicated nor capped, and each costs two queries
- Where: `backend/apps/proposals/logic.py`:206
- Scenario: payload.terms = ["legal_entity:bank"] repeated 100k times (about 2 MB, under Django's 2.5 MB body limit). _validate_obligation_payload calls term_by_ref per element, and term_by_ref runs dimension_by_key plus a term query each time, so one request runs about 200k sequential queries in its transaction. It is then stored twice: in proposal.payload and in the audit row's after. Even two duplicates are stored as is, and T6's brief says apply 'replaces the obligation's ObligationTerm links', so a straightforward create per term hits obligation_term_unique (library/models.py:425) and approval fails with an IntegrityError. This is exactly the unappliable queue item validated_payload's docstring promises never to admit.
- Fix: Refuse duplicate refs (or de-duplicate before storing), cap the count with a setting that has an env override (for example PROPOSAL_MAX_TERMS), and resolve all refs in one query. Local main already does this in apps/library/reading.py _terms_of(): make it public and reuse it instead of a second parser.

### [LOW] correctness: An idempotent replay ignores targetId, fieldSources and who is replaying, now that proposals carry a tenant
- Where: `backend/apps/proposals/logic.py`:300
- Scenario: (a) An agent reuses Idempotency-Key K with the same title and payload but a different targetId, or corrected fieldSources. It gets 200 with the first proposal and the second is silently lost, although the module docstring promises 409 idempotency_conflict for a different body. (b) idempotency_key is globally unique. Tenant B's agent sends a K that tenant A's agent already used, with the same kind, title and payload. It gets A's proposal back (proposedBy, agentRunId, changeId), and line 312 writes a proposal.replayed audit and outbox row under tenant B for a proposal that proposal_tenant links only to A. (c) _validate_obligation_target runs before the replay lookup (line 287), so a retry after the target was retired answers 422 unknown_key instead of the proposal already made.
- Fix: Compare (kind, title, payload, target_type, target_id, field_sources). Scope the replay lookup to the same proposer (proposed_by_api_key or proposed_by_user), or answer idempotency_conflict when the proposer differs. Run the idempotency lookup before the target and source checks.

### [LOW] conflict: Textual merge conflict with local main
- Where: `backend/apps/shared/tests_rls.py`:58
- Scenario: git merge-tree main REF reports CONFLICT in tests_rls.py. Main appended "agent_run" and the branch appended "proposal_tenant" to the same tuple in test_enumeration_finds_the_mixed_tables.
- Fix: Keep both entries in the tuple, along with both comments. Main's new test_only_the_named_policies_sit_beside_the_tenant_policy passes for proposal_tenant as is, because rls_operations creates only tenant_isolation.

- Verification of "A field source is any non-blank string: no link check, no length cap, and keys that name no changed field are accepted": refuted=False, severity after=MEDIUM. Reproduced on REF (origin/claude/c4-t1-obligation-proposals-00zwiq); no guard elsewhere stops it.

1. The check is blank-only. backend/apps/proposals/logic.py:249 `missing = [field for field in sourced_fields(payload) if not field_sources.get(field, "").strip()]` is the whole rule; `check_field_sources` raises only `source_missing`. Nothing tests scheme, shape or length, so "n/a", "see above" and "javascript:alert(1)" all pass.

2. Every key is stored verbatim, including keys naming no changed field. logic.py:288 `sources = field_sources or {}` and logic.py:320 `field_sources=sources` write the caller's dict as-is; `sourced_fields()` (logic.py:226-238) is only used to compute what is missing, never to reject extras. The request type is `field_sources: dict[str, str]` (backend/apps/proposals/schemas.py:180, and `ProposalFieldSources(RootModel[dict[str, str]])` at schemas.py:128), so `WriteBody`'s `extra="forbid"` (backend/apps/shared/schemas.py:29) does not apply to the dict's keys. The values are also returned to the console unchanged through `row()` (logic.py:398).

3. No length cap. `field_sources = models.JSONField(default=dict, blank=True)` (backend/apps/proposals/models.py:71) is a free JSONB column; the branch's tests (backend/apps/proposals/tests_create.py:119-148) only cover a missing or whitespace source. `grep DATA_UPLOAD_MAX` over backend/config finds no override, so Django's default 2.5 MB body cap is the only bound and the 2 MB example goes through. Main has meanwhile added LIBRARY_TEXT_MAX_CHARS to sentence_diff precisely because untrusted proposal text needs a cap (git diff base..main -- backend/apps/library/logic.py), which reinforces the point.

4. No guard elsewhere. `git grep URLValidator|full_clean` over backend/apps on REF returns nothing outside sentry_scrub; the create route (backend/apps/proposals/api.py:61-80, unchanged on the branch) forwards `body.field_sources` straight to `logic.create`; apply.py never reads `field_sources`. PRO-S10 (app.md:149-163 on REF) and D-35 (docs/DECISIONS.md:44, "field sources on a standard's records must be URLs") only cover standards and are still pending, so they do not cover an ordinary obligation. The documented rule is a link: docs/inputs/schema.sql:379 `field_sources ... -- one source link per changed field`, PRD.md:161 and app.md PRO-S1 "each changed field carries a source reference".

One premise of the finding is overstated but does not change the outcome: the contrast with `source_url` (models.py:73, `URLField(max_length=2000)`) holds only for length, which the varchar column enforces; the URL format validator never runs because `Proposal.objects.create` does not call `full_clean()`, so `source_url` is equally unvalidated today. That makes the proposed fix (one URLValidator applied in `check_field_sources`, mirrored for `source_url` if the owner wants) the right shape, and it belongs in the one function so the approval re-check inherits it.

Severity: MEDIUM stands. Mitigating: only an authenticated proposer (session permission or an API key with proposals:write) can submit, a reviewer sees the value before approval, and nothing from `field_sources` is written to the library by apply.py, so this is not a direct library write or an unauthenticated vector; the `javascript:` concern only bites if the future console renders the value as an href. Aggravating: CLAUDE.md §5 names validation at a trust boundary (user, agent, network input) as a safeguard that is never simplified away, PRO-01 is the requirement the branch claims to build and it is met in form only, and the stored strings are agent-supplied content shown to platform reviewers with no cap.

Conflict note: local main does not touch backend/apps/proposals/logic.py, schemas.py or models.py since the merge base (its changes on the same paths are only library/logic.py sentence_diff caps and tests_rls.py), so the fix in `check_field_sources` will not collide with main.
