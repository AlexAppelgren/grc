Evaluation card (/console/evaluation). It sits in the console rail in the library editor's group, beside Sources, and its denied state names eval manage; a platform admin never sees it. The page reads the whole set and filters it by the languages the set holds. Each question carries three pills, every one from the question's own facts: whether the release gate scores it (In the release gate is positive; Not yet in the release gate is a warning, because someone must write it to the gate's file and ship it; Retired is a plain fact), its language and how it should be won, both information. A run on stand-in models is a warning pill: its scores say nothing about a real model. The baseline is the release gate's own, read from the build; a metric nobody recorded reads Unrecorded and never zero, because zero would claim search found nothing. Adding a question asks for no passkey: it is a test of search, not a decision about the law, it is never edited and it changes no library record. The form says before and after that the question is not yet in the release gate. There is no retire or edit control and no "run now": a run takes minutes in a database of its own and waits for chunk 14's job runner. Questions, keys and scores are sample data.
