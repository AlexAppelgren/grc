Agent keys card (/console/agent-keys). It sits in the console rail under the platform admin's group, beside Tenants, and its denied state names the permission it needs; a library editor reviewing proposals never sees it. Each key belongs to no organisation and to exactly one agent, so the actor behind every row the key writes is that agent and not the person who made the key. The scope list is the fixed one the API knows, shown as information pills on a row and as a checkbox with a plain description in the form; nothing here writes to the library, because an agent proposes and a person approves. The agent version is a brand pill, Active and a finished state are positive, Revoked and Expired are warning, and "Never used" is a plain information pill: every one of them comes from the row's own facts, never from a choice. Creating a key asks for a passkey, as every key creation does, because the key can act on its own from the moment it exists; revoking asks once in a dialog and needs no passkey, because it only takes access away. The plain key is shown once, on the surface and not in a coloured banner, and only its prefix survives a reload, because the server keeps a hash. Revoked and expired keys stay in the list so the security log and the audit trail still have something to point at. The permission drawn here is the platform admin's agent definitions manage, the documented default for platform-owned agent work; the names, prefixes and dates are sample data and the key on screen is not a real one.
