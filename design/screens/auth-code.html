Code card, step one of enrolment. From the invitation link the page asks for the code alone: the link's token names the account and is verified with the code (POST /auth/invitations/verify, token in the body), held in memory only, never in the address or storage. "Send a new code" opens the same invitation again. After a reload the token is gone, so the card asks for the link again rather than an address. The sign-in page's "First time here?" path asks for the address too, and its "Send a new code" always answers the same neutral sentence (an enrolled address gets nothing and learns nothing). The code is one input behind six slots: paste fills them all, the phone offers the code from the mail, and the form submits on the sixth digit. The wrong-code and locked states branch on the server's code, never its text. Submitting a right code moves to auth-enrol.html.
